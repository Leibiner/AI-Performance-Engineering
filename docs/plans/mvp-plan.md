# MVP 计划

> 日期：2026-09-30 ｜ 状态：执行中
> 接口约定见 `docs/plans/mvp-contract.md`。

## 1. 目标

做出一个能在 Windows 浏览器里使用的最小可用版本：在页面上维护接口、业务流程、负载配置、验收标准和环境，点按钮发起压测，看到判定和指标，结果自动存档。

## 2. 已确认的决定

| 事项 | 决定 | 确认时间 |
|---|---|---|
| 压测目标 | 直接请求 `https://www.baidu.com`，只允许冒烟级别流量（环境上限：2 并发、每秒 2 次、60 秒） | 2026-09-30 |
| 前端定位 | 可维护的管理控制台：接口与业务流程、负载配置与验收标准、环境与目标地址都能在页面上增删改；能从页面发起和停止压测；查看结果；历史存档 | 2026-09-30 |
| 存储 | SQLite 单文件（`data/app.db`） | 2026-09-30 |
| 前端技术栈 | Vue 3 + TypeScript + Vite + Element Plus + ECharts | 2026-09-30 |
| 提交方式 | 每批提交到 `main`，push 由用户执行 | 2026-09-30 |
| 环境与依赖管理 | 用 uv 管理（`pyproject.toml` + `uv.lock`），因此后端用 Python | 2026-09-30 |
| 测试 | 禁止过度测试：不写单元测试套件，只用真实运行验证主流程 | 2026-09-30 |

这些决定改变了 Phase 0 的两项设计：前端从"只读控制台"变为"可维护的管理控制台"（原 ADR-004），业务流程从"手写 JS 代码"变为"页面上定义的数据"。文档在第 3 批同步修订。

## 3. 技术方案

| 部分 | 方案 |
|---|---|
| 环境与工具链 | Python 依赖由 uv 管理（`uv sync` 装到 `.venv/`）；k6 v2.3.0 和仅用于构建前端的 Node v24.21.0 由 `scripts/setup.sh` 下载到 `.tools/`，不需要 sudo |
| 执行引擎 `perf/` | 一个通用的 k6 脚本 `perf/runner.js`，读取后端生成的 `plan.json` 解释执行；`perf/core/` 负责生成 scenarios、阈值和 Run Record |
| 后端 `server/` | Python 3.12 + FastAPI + 标准库 `sqlite3`；负责增删改查、预检、启动和停止 k6、保存运行存档、托管前端。用 `uv run` 启动 |
| 前端 `web/` | Vue 3 + TypeScript + Vite + Element Plus；依赖用 npm 管理（uv 只管 Python）；构建产物由后端托管 |
| 访问方式 | 后端监听 `0.0.0.0:8088`，Windows 浏览器访问 `http://192.168.0.136:8088` |

保留的核心设计：业务（接口、流程）与负载（负载配置）分开维护；负载模型显式区分 open / closed；SLO 是数据，阈值由它生成；判定区分 `failed`（系统不达标）和 `invalid`（测试本身不可信）；每次运行有 runId 和完整记录。

## 4. 分批执行

| 批次 | 内容 | 执行者 | 产出 |
|---|---|---|---|
| 0 准备 | uv 项目骨架、工具链、`.gitignore`、计划、契约、记录文档 | 主会话 | `pyproject.toml`、`uv.lock`、`scripts/`、`docs/plans/mvp-*.md`、`docs/records/` |
| 1 并行开发 | A 执行引擎：`perf/`，用真实 k6 对百度做冒烟验证<br/>B 后端：`server/`，数据表、种子数据、接口、运行编排<br/>C 前端：`web/`，7 个页面 | 3 个 agent 并行，目录互不重叠 | 三部分代码 |
| 2 联调启动 | 三部分接起来，端到端跑通一次冒烟；写 `scripts/start.sh`、`stop.sh`；启动服务 | 主会话 | 可从 Windows 访问的服务 |
| 3 文档同步 | 修订 `ARCHITECTURE.md`、新增 ADR-005、更新 `CLAUDE.md` 和路线图 | 1 个 agent + 主会话核对 | 文档与实现一致 |

每批结束后提交一次，并在 `docs/records/commit-log.md` 记一条。过程中用到的技术按类别记入 `docs/records/tech-notes.md`。

## 5. MVP 功能清单

| 页面 | 功能 |
|---|---|
| 概览 | 各类定义的数量、判定分布、最近的运行 |
| 环境 | 增删改查：名称、基础地址、公共请求头、流量上限 |
| 接口 | 增删改查：方法、路径、请求头、请求体、期望状态码、期望包含的文本、变量提取 |
| 业务流程 | 增删改查：按顺序排列接口步骤，设置每步的等待时间 |
| 负载配置 | 增删改查：类型、open / closed 模型、并发或到达率、时长 |
| 测试 | 增删改查：选择流程和权重、设置验收标准；发起运行（选负载配置和环境） |
| 运行 | 列表（筛选、存档、删除）；详情（判定、有效性、阈值结果、分步骤指标、图表、k6 图表、产物）；运行中可停止 |

## 6. 不在 MVP 范围内

登录与权限、多个运行同时进行、基线对比与趋势、Prometheus / Grafana 接入、CI、分布式执行、任何 AI 功能、HTTP 以外的协议。

## 7. 验收

1. Windows 浏览器能打开 `http://192.168.0.136:8088`
2. 在页面上新建一个接口、流程、测试，用"冒烟"配置对百度环境发起运行，运行结束后看到判定和指标
3. 把验收标准改得很严（例如 p95 < 1 ms）再运行，判定为 `failed`
4. 选一个超过环境上限的负载配置发起运行，被预检拒绝并说明原因
5. 运行记录在重启服务后仍然存在，可以存档和删除
