# 技术笔记

记录实现过程中实际用到的技术、踩到的坑和做出的取舍，按类别整理。只记**已经验证过**的内容；没验证的写明"未验证"。

## 1. 工具链与环境

| 主题 | 内容 | 日期 |
|---|---|---|
| uv 管理环境与依赖 | 按用户要求，Python 环境和依赖统一用 uv 管理：`pyproject.toml` 声明依赖，`uv.lock` 锁定版本，`uv sync` 创建 `.venv/`，`uv run <命令>` 在该环境里执行。本机已有 uv 0.11.18。`[tool.uv] package = false` 表示项目不打包安装，代码直接从 `server/` 运行 | 2026-09-30 |
| 免 sudo 安装工具 | 本机没有 sudo 权限，也没有 Docker。k6 和 Node 都提供免安装的压缩包，解压到项目内的 `.tools/` 即可使用；`scripts/setup.sh` 固定版本，`source scripts/env.sh` 把它们放到 PATH 最前面 | 2026-09-30 |
| Node 只用于前端 | uv 只管 Python，前端（Vue）的依赖仍然用 npm。系统自带 Node v18.19.1 已停止维护，项目用自带的 Node v24.21.0 构建前端 | 2026-09-30 |
| k6 版本 | k6 v2.3.0，从 GitHub Releases 下载 `k6-v2.3.0-linux-amd64.tar.gz` | 2026-09-30 |
| 从 Windows 访问 | 服务器地址 `192.168.0.136`，用户从 Windows 通过 SSH 连接。服务监听 `0.0.0.0`，浏览器直接用 IP 加端口访问。8088 和 5665 端口经检查未被占用 | 2026-09-30 |
| git push | 在 agent 会话里执行 `git push` 会一直卡住（凭据需要交互），由用户在终端执行 `! git push` | 2026-09-30 |
